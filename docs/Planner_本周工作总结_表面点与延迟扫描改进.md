# Planner 本周工作总结

## 一、本周工作概述

本周主要解决了两类问题：

1. 建筑、高楼等大型目标不再把物体中心作为接近和完成判定基准，而是使用深度观测得到的真实表面点或有限表面片。这样可以避免无人机朝建筑内部、楼体中心或不可达位置飞行。
2. “转向后当前视野中的第 N 个目标”不再被任务启动扫描提前绑定，而是在对应阶段真正开始时，根据当时的 RGB、深度、位姿和朝向重新建立局部目标编号。同时，普通未来目标扫描改为后台异步执行，减少扫描对当前飞行的阻塞。

一句话总结：本周把目标定位从“语义中心点”推进到了“可到达表面”，并把视角相关目标从“提前猜测”改成了“到阶段再绑定”。

## 二、表面点改进

- **原有问题：** 原有方案使用单一中心目标点表示物体位置。对于建筑、高楼等大型目标，单点可能位于楼体内部或只代表局部位置，无法准确描述建筑的可达边界，容易导致规划器持续向建筑内部推进。

- **多表面点表示：** 本周将单点表示改为多表面点表示。系统利用不同视角下检测框内的深度信息，持续提取建筑外墙上的多个表面采样点及有限表面区域，并将其投影到世界坐标中，形成更加完整的目标表面几何信息。

- **导航与完成判断：** 系统优先选择距离无人机最近的可达表面点作为导航目标。对于大型目标的“旁边/附近”任务，改为计算无人机到全部有效表面采样点的最小水平距离，不再以楼体中心或某一个固定点作为到达依据。

- **路径安全与近场稳定性：** 当航迹首次进入任一有效表面点的完成范围时，系统会裁剪后续路径并及时停车，减少穿过建筑或飞过完成区域的问题。当近距离墙面铺满画面、完整建筑检测能力下降时，系统仍可利用已经锁定的多表面点记忆继续导航和完成判断，避免目标距离突然跳变或重复重定位。

## 三、延迟扫描与延迟绑定改进

- **适用任务：** 延迟绑定主要用于“当前视野中的目标”“转向后的第二栋楼”“新视角前方的目标”等依赖阶段实时视角的任务。

- **绑定时机：** 这类目标不再参与任务开始时的提前扫描，也不会被未来目标扫描提前确定。系统会等待前序移动或转向完成，在对应阶段真正激活后再进行扫描和目标绑定。

- **绑定依据：** 阶段激活时，系统会重新获取当前图像、同一时刻的深度信息、无人机位置和朝向，并以这一视角重新建立局部候选及目标顺序，避免使用任务初始视角或历史画面选错目标。

- **防止误绑定：** 系统会根据指令限制候选目标的方向和空间范围。目标实例锁定后，远处的同类目标不能直接替换当前实例，从而减少多栋相似建筑场景中的目标切换问题。

- **降低扫描延迟：** 普通未来目标扫描改为独立后台线程低频执行，当前飞行不需要等待扫描完成。扫描结果返回后会再次检查任务和阶段是否有效，过期或跨阶段结果会被丢弃，避免延迟结果污染当前目标记忆。

## 四、当前缺陷与待完善项

当前规划器缺乏有效的避障措施。

此外，在城市高楼场景中，规划器对建筑间穿梭类任务的支持仍较有限。目前任务通常需要指定明确的建筑作为目标，系统主要执行“飞向某栋建筑”的导航，尚不能稳定理解并完成“从两栋建筑之间穿过”“沿建筑群间的通道飞行”等以空间区域或通行关系为目标的任务。
