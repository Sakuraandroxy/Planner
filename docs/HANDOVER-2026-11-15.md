## 4 分层与依赖

```
① 界面      console + HTTP API
② 服务编排  server_controller / server_bootstrap   ← 拥有 hub、日志汇、帧汇
③ 装配      application/mission_assembly.py        ← 唯一知道"谁需要什么"
④ 任务循环  workflows + services(execution/motion/hub)
⑤ 能力      capabilities(检测几何、滑窗、完成判定)
⑥a 规划器   adapters/{task_parser,trajectory_planner,detector,completion}   ┐ 并列
⑥b 仿真器   simulators/{airsim,projectairsim} + simulator/{驱动,worker}      ┘
⑦ 领域与端口 domain/(纯数据) + ports/(协议)      ← 所有人依赖它,它不依赖任何人
```

三条不变量:

1. **并列件不构造并列件。** 仿真器会话不再接收 `detector`/`planner`/`geometry`/遥测汇。
2. **只有装配层知道全部。** 少接线在构造期报错,不静默降级。
3. **能力门只回答"这台引擎能不能做"。** 进程边界(UE4 在子进程)是部署事实,不改变功能归属。

## 8 踩过的坑(别再踩)

- **用 curl 起图后判断前端行为。** 没有 xpra 客户端接上时桌面帧是冻结的(实测整圈机位切换后签名相关度 1.0000、平均像素差 0.00)。操作员起图必然在页面上,别为"没人看"写适配代码。
- **默认载具是 `rover`。** 给 UE4 提交任务必须带 `vehicle:"drone"`,否则 `AirSim drives a drone only`。
- **Shanghai 图是坏的打包。** 载具出生即卡进几何体(`FindTeleportSpot ... intersecting geometry`),掉到 z=3000 米还在自由落体,`_wait_ready` 因速度不静默而超时。用户确认是自己打包问题,不是代码。
- **`landed_state` 不可信。** 落地后仍返回 1(Flying)。起飞与否按实测地面高度判。
- **`takeoffAsync`/`moveToPositionAsync` 的 bool 返回不可信。** 完成判定一律看状态。
- **UE5 一个实例只接一个 ProjectAirSim 客户端。** 取参考帧要另开连接,与主连接抢同一 topic 链路,是起图卡住的一个来源。
- **`switch_streaming_view` 只在渲染帧上生效。** 场景时钟 `steppable` + `pause-on-start`,不推进就没有新帧。任何等画面的循环都要继续推时钟。
- **前端门控必须按卡片 id。** 见 `8ef51dd`。
- **`xpra_start.py` 到 600 行还没拆**:`ownership` 与 `probes` 读同一份家族视图,拆文件要把 6~9 个字段原样再传一遍,行数搬家而耦合不减。真要拆,先拆出"家族视图"数据对象。
