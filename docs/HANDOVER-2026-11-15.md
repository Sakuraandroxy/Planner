## 3 下一步：UE4 控制面三处冲突

顺序 **① → ② → ③**，细节与实测数据在 `UE4_REMAINING_WORK.md` 7.3。

1. **载具名**。`/data/airsim/settings.json` 里载具叫 `Drone_1`，适配层所有调用都不传
   `vehicle_name`。空名下 `moveToPositionAsync` 返回 `False`、`landAsync("")` 抛 `RPCError`。
   按第 1 节的决定，名字进家族段，`AirSimConnection` 与各处调用把它传下去。
2. **动作完成判据**。`planner/simulators/airsim/vehicle.py:58` 把异步返回值当成败依据。
   实测：显式传名并 `enableApiControl` + `armDisarm` 后，无人机确实从 z=-0.60 爬到 -1.59，
   `.get()` 仍返回 `False`。判据改成状态驱动（位置收敛 + `landed_state`，枚举已在 7.1 核实）。
3. **深度分辨率**。主干 `Observation.__post_init__` 要求 `depth_m.shape == rgb.shape[:2]`，
   而 1280x720 的米制深度单帧 `capture()` 实测 **25.97 秒**（纯 Python msgpack 解 92 万个 float），
   256x256 约 0.2 秒。走 C 方案放宽契约，改 `planner/domain/observation.py`——这是 UE5 共用的，
   改完两族都要实机跑，先确认 UE5 侧有没有等价测试覆盖它（没有就先补测试再改）。

三条修完才谈得上 UE4 任务级端到端，那时才用密钥。
