# 模型与功能解耦重构说明

## 目标

这次重构的核心目标是把“模型后端”和“闭环功能”拆开：

- 模型层只关心如何调用一个具体后端，例如 GroundingDINO、云端 VLM、本地 Qwen LoRA。
- 功能层只关心闭环里要完成什么事情，例如目标检测、任务完成判定、滑动窗口规划、快慢系统调度。
- 主循环不再直接理解某个模型的 API 细节，也不直接处理 incremental/cumulative/world 坐标转换细节。

旧入口仍然保留：

- `run_airsim_web.py`：旧版累计 body-frame waypoint 闭环。
- `run_airsim_web_sliding_window.py`：滑动窗口闭环，当前已改为使用新的 `WorldTrajectoryQueue` 包装，但行为保持一致。
- `run_airsim_web_fast_slow.py`：新增实验入口，用于之后接入真正异步的快慢系统。

## 轨迹语义

滑动窗口微调版 Qwen 的输入输出都是 incremental body-frame waypoint：

```text
pending:    [[dx1,dy1,dz1], [dx2,dy2,dz2], ...]
additional: [[dx3,dy3,dz3], [dx4,dy4,dz4], ...]
```

每个点都表示“相对于上一个轨迹点的位移”。第一个 pending 或 output 点相对于当前无人机位置。

运行时队列存 absolute world waypoint，Qwen I/O 则保持和训练集一致的 incremental body-frame waypoint。因此新队列规则是：

- 队列内部存 absolute world waypoint。
- 给 Qwen 前，用提交规划时的 current pose/yaw 把队列剩余 world waypoint 转成 incremental body。
- Qwen 输出 additional incremental body 后，用提交规划时的 same pose/yaw 转回 absolute world waypoint。
- AirSim 执行前，把队列前几个 world waypoint 转成执行时 current pose/yaw 下的 cumulative body waypoint。
- 继续使用 `execute_waypoints` 执行，避免改底层执行器语义。

## 快慢系统设计

快系统：

- 持续从 world 队列取前 `EXECUTE_COUNT` 个点执行。
- 周期性运行任务完成判定。
- 碰撞后清空队列并按原碰撞恢复逻辑后退。

慢系统：

- 当队列长度低于 `LOW_WATERMARK` 时，后台调用 Qwen。
- 提交 Qwen 请求时保存当时的 `plan_pos` 和 `plan_yaw`。
- Qwen 返回后，必须用提交时的 pose 把 additional incremental 转成 world，而不是用返回时的 pose。

这个规则很重要，否则无人机在等待 Qwen 时已经移动，轨迹追加会发生参考系漂移。

## 配置方式

解耦配置模板在：

```text
config/decoupled_example.yaml
```

功能层选择功能实现：

```yaml
FUNCTIONS:
  PLANNING:
    NAME: sliding_window_planning
    MODEL: qwen_incremental
```

模型层选择具体后端：

```yaml
MODELS:
  qwen_incremental:
    NAME: qwen_incremental
    TYPE: planner
    WAYPOINT_FORMAT: incremental_body
```

长 Python 路径不写进 yaml，统一放在 `agent/core/registry.py`。这样以后换模型，只改 `MODELS` 或 `AGENT` 中的模型配置；换功能策略，才改 `FUNCTIONS`。

## 当前影响范围

- 旧 `run_airsim_web.py` 未改动。
- 现有滑窗入口只把队列类替换成 `WorldTrajectoryQueue`，该类继承原 `SlidingWindowTrajectoryQueue`，方法语义一致。
- 新增的模型/功能目录通过明确命名的模型入口复用现有实现，不会改变旧 API 行为。
- 快慢系统控制器已经新增，但完整异步执行循环还没有强行替换旧滑窗主循环，避免影响当前可跑版本。

## 下一步接入点

真正启用快慢双系统时，只应该改新增入口 `run_airsim_web_fast_slow.py` 或新增 runtime loop，不应该再改旧入口。

推荐顺序：

1. 用明早微调好的滑窗 Qwen 先跑 `run_airsim_web_sliding_window.py`，验证 incremental 输出是否正常。
2. 再在 `run_airsim_web_fast_slow.py` 中把 step-level 等待循环替换成 `FastSlowController`。
3. 队列低于 3 个点时后台补轨迹，执行端每次只飞 1 个点。
4. 完成判定每 1.5 秒检查一次，done 后清空队列并切阶段。
5. 如果快慢系统不稳定，直接回退到滑窗入口或旧入口。
