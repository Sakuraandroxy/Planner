# 滑动窗口轨迹规划与世界模型接入设计

## 1. 当前目标

现有闭环流程是：

```text
取图 -> 任务解析/目标检测 -> planner 输出轨迹 -> 世界模型打分 -> 执行轨迹
```

目前主要瓶颈在 VLM/Qwen 输出轨迹。取图中前视深度较慢，前视图和下视图本身较快；目标检测也相对较快。本地 Qwen 后续规划输入只需要前视图、下视图和任务目标，不强依赖深度图与检测结果。因此可以考虑把“规划”和“执行”做成滑动窗口，让无人机执行当前轨迹时，Qwen 在后台继续预测后续轨迹，尽量减少停等。

## 2. 世界模型输入轨迹格式

世界模型不需要相对偏航，因为实际飞行时执行器会先转向下一个轨迹点方向，再直飞到该点。世界模型只需要看到三维位移序列。

Qwen planner 输出的是相对于当前起始位置的累计 body-frame waypoint：

```text
[[x1,y1,z1], [x2,y2,z2], ...]
```

送入世界模型前，需要转换成相邻 waypoint 的相对位移：

```text
[[x1,y1,z1], [x2-x1,y2-y1,z2-z1], ...]
```

API 原子规划器输出的是原子动作，例如：

```text
["forward 3", "left 90", "forward 4"]
```

需要先转换成无偏航的累计 waypoint：

```text
[[3,0,0], [3,-4,0]]
```

再转换成世界模型输入：

```text
[[3,0,0], [0,-4,0]]
```

注意：转向动作本身不单独生成 waypoint，也不把 yaw/dphi 送入世界模型。

这里采用当前项目的 body-frame 约定：初始前方是 `+x`，左转后继续前进对应 `y` 负方向，右转后继续前进对应 `y` 正方向。

实际运行时需要区分不同轨迹形态。Qwen planner 至少会涉及三种形式：

```text
1. Qwen 原始输出：相对当前起点的累计 body-frame waypoint
2. 世界模型输入：相邻 waypoint 的相对位移，不含 yaw
3. AirSim 执行输入：由累计 body-frame waypoint 转换得到的世界坐标路径
```

API 原子规划器会多一层原子动作形式，因此至少涉及四种形式：

```text
1. API 原始输出：原子动作，例如 forward/left/right/up/down
2. 候选轨迹累计点：原子动作转成相对当前起点的累计 body-frame waypoint，不含 yaw-only 点
3. 世界模型输入：累计点再转成相邻 waypoint 的相对位移，不含 yaw
4. AirSim 执行输入：执行链路将动作或累计点转换成最终世界坐标路径
```

## 3. 平滑桥扰动与默认行为

默认不启用扰动功能。此时世界模型只接收 planner/Qwen 的一条原始轨迹。

当 `CANDIDATE.ENABLE_SMOOTH_BRIDGE=true` 时，候选模块会基于原始累计 waypoint 生成多条平滑桥候选。平滑桥固定隐式起点 `[0,0,0]` 和最终 waypoint，只扰动中间 waypoint，然后再把候选转换成世界模型需要的相邻位移格式。

推荐配置入口：

```yaml
CANDIDATE:
  ENABLE_SMOOTH_BRIDGE: false
  TOPK_FOR_WORLD_MODEL: 3
  MAX_GENERATED: 8
  SMOOTH_BRIDGE_LATERAL_SIGMA_M: 1.0
  SMOOTH_BRIDGE_VERTICAL_SIGMA_M: 0.25
  SMOOTH_BRIDGE_LENGTH_SCALE: 0.35
  SMOOTH_BRIDGE_MAX_TURN_DEG: 120.0
  SMOOTH_BRIDGE_MAX_PATH_LENGTH_RATIO: 1.5
```

## 4. 滑动窗口规划思路

假设当前 Qwen 一次输出 5 个轨迹点：

```text
x1, x2, x3, x4, x5
```

无人机开始执行这条轨迹。当无人机飞到某个窗口触发点，例如 `x1` 或 `x2` 时，如果 Qwen 空闲，就用当前帧、任务目标和剩余轨迹作为输入，让 Qwen 预测后续轨迹。

例如无人机到达 `x1` 后，输入给 Qwen：

```text
当前前视图
当前下视图
任务目标
剩余轨迹 x2, x3, x4, x5，其中这些点要转换成相对于 x1 的累计/相邻表达
```

Qwen 输出后续新点：

```text
x6, x7, x8
```

系统将这些点拼接到待执行队列后面：

```text
x2, x3, x4, x5, x6, x7, x8
```

这样无人机不用等当前 5 个点全部执行完再停下来重新规划，而是在执行过程中持续补充未来轨迹。

## 5. 训练数据变化

当前正在微调的模型任务是：

```text
输入：当前前视图 + 下视图 + 任务目标
输出：一整条累计 waypoint 轨迹
```

滑动窗口版本需要一个新的训练任务：

```text
输入：当前前视图 + 下视图 + 任务目标 + 剩余待执行轨迹
输出：接下来的一个或多个新 waypoint
```

训练样本可以从现有轨迹中切片构造。例如一条完整轨迹为：

```text
x1, x2, x3, x4, x5, x6, x7, x8
```

可以构造样本：

```text
当前帧在 x1 附近，输入剩余轨迹 x2-x5，输出 x6-x8
当前帧在 x2 附近，输入剩余轨迹 x3-x6，输出 x7-x8
```

这里需要统一坐标表达：输入的剩余轨迹和输出的新轨迹都应以当前无人机位置为新的 body-frame 起点。

## 6. 与世界模型的关键问题

滑动窗口会带来一个问题：Qwen 在后台输出后续候选时，无人机可能还没有执行完当前窗口。此时如果要让世界模型判断哪条候选更好，不能等到全部执行完再取图，否则会失去提前规划的意义。

推荐解决方式是：把“当前还没执行完的公共轨迹前缀”和“待接入的候选后缀”拼成完整候选，再交给世界模型。

例如当前待执行队列是：

```text
x2, x3, x4, x5
```

Qwen 生成了 K 条后续候选：

```text
A: x6a, x7a, x8a
B: x6b, x7b, x8b
C: x6c, x7c, x8c
```

送入世界模型时构造成：

```text
候选 A: x2, x3, x4, x5, x6a, x7a, x8a
候选 B: x2, x3, x4, x5, x6b, x7b, x8b
候选 C: x2, x3, x4, x5, x6c, x7c, x8c
```

这些候选的前半段完全相同，差异只在后续接入部分。世界模型基于当前帧、任务目标和完整候选轨迹打分，选择最适合接到队列后面的那条。

该方案可行，因为世界模型评分的是“从当前状态出发的未来轨迹整体质量”，即使前面几个 waypoint 已经确定，也可以比较不同后缀对最终导航的影响。

## 7. 运行时队列设计

可以维护一个待执行轨迹队列：

```text
pending_waypoints = [x2, x3, x4, x5]
```

执行线程持续取队列头部 waypoint 执行。规划线程在满足条件时异步启动：

```text
Qwen 空闲
pending_waypoints 数量低于阈值
当前帧已更新
任务尚未完成
```

规划线程输出新候选后，经过平滑桥扰动和世界模型打分，选出一个后缀拼接到队列末尾。

推荐触发条件：

```text
pending_waypoints <= 2 时触发补轨迹
或飞到第 1/2 个 waypoint 后触发补轨迹
或预计剩余执行时间 < Qwen 平均推理时间时触发补轨迹
```

## 8. 任务完成判定

当前不立即实现滑动窗口，是因为还缺少稳定的任务完成判定。

本地 Qwen planner 本身不需要深度图和目标检测，但未来可以加入双 agent：

```text
Planner agent：只看前视图、下视图、任务目标，负责连续补轨迹
State agent：按需调用深度图和目标检测，判断任务是否完成或是否需要重新定位目标
```

State agent 可以在以下情况触发重检测：

```text
待执行轨迹快结束
世界模型评分持续偏低
无人机长时间没有接近目标
任务语义需要确认到达，例如“飞到目标旁边”
```

## 9. 主要风险

第一，滑动窗口训练数据和当前完整轨迹训练数据不是同一个任务，需要重新构造样本，否则模型可能不知道如何利用“剩余轨迹”这个条件。

第二，坐标系必须严格统一。每次滑动窗口输入和输出都要以当前无人机位置为新起点，否则拼接后的轨迹会漂移。

第三，世界模型看到的候选轨迹应该是相邻位移，不应包含 yaw。执行器内部可以根据相邻 waypoint 自动转向。

第四，后台 Qwen 输出可能晚于无人机执行速度。如果输出太慢，队列仍然会耗尽并产生等待。因此需要根据 Qwen 平均耗时和 waypoint 执行时间设置触发阈值。

第五，候选后缀接入时要检查连续性。新后缀的第一个点必须和当前队列末尾平滑衔接，不能出现突然大转角或大高度跳变。

## 10. 后续实现顺序

建议之后按以下顺序实现：

1. 先稳定世界模型输入格式：所有候选统一为相邻 body-frame 位移，不含 yaw。
2. 加入轨迹队列执行器：从一次性执行整条轨迹改为按 waypoint 队列逐段执行。
3. 加入异步 Qwen 规划线程：在队列低水位时基于当前帧和剩余轨迹补后续点。
4. 构造滑动窗口微调数据：输入当前帧、任务目标、剩余轨迹，输出后续 waypoint。
5. 接入世界模型：把公共前缀和 K 条候选后缀拼成 K 条完整候选进行打分。
6. 加入任务状态 agent：按需检测目标、深度和完成状态，避免 planner 无限补轨迹。
