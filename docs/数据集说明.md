# 3DG-VLN / UAV-VLN-FOV 数据集使用说明

## 数据集是什么

3DG-VLN 使用的数据集叫 **UAV-VLN-FOV**，包含 2,717 条轨迹，每条轨迹有：

- 高分辨率前视+下视图像
- 简洁的高级指令（约 12 个词）
- 连续的 3D waypoint 标注
- 起始位姿和目标位置

## 数据集的两种用途

### 1. 训练 Qwen2.5-VL LoRA（有监督学习）

```
train split (2228条)
  每条轨迹: (前视图, 下视图, 指令, 初始方向) → 真值 waypoints
                                                  ↓
                                         Qwen2.5-VL LoRA 微调
                                         标准 instruction tuning
```

- 图像是**预录的**（数据集中的图片文件）
- 模型看到的是训练集里固定的图像
- 方向用初始位姿和目标位置算出来，不更新

### 2. 评估导航性能

```
test / unobject / unscene 三个 split
  每条轨迹只取:
  ├─ 起始位姿 (x, y, z, yaw) → 初始化仿真器
  ├─ 目标位置 (x, y, z)       → 算指标时的 GT
  └─ 指令文本                  → 输入给模型
        ↓
  仿真器从起始位姿启动，无人机每步看到的都是【实时渲染】的图像
  （不是数据集里的预录图像！）
        ↓
  跑最多 100 步闭环 → 停在哪就算哪 → 算 SR/OSR/NE/SPL
```

**评估时看到的图像是全新的，不是训练时见过的。**

## 为什么只需要起始位姿和目标位置

评估不需要预录图像，因为：

| 需要什么 | 从哪里来 | 用途 |
|---|---|---|
| 起始位姿 | 数据集（mark.json） | 仿真器初始化 |
| 目标位置 | 数据集（mark.json） | 指标 GT |
| 指令文本 | 数据集（object_description.json） | 模型输入 |
| 每步的图像 | **仿真器实时渲染**（不是数据集里的） | 检测+规划 |

## 数据集 splits 说明

| Split | 数量 | 用途 | 图像来源 |
|---|---|---|---|
| train | 2,228 条 | LoRA 微调 | 预录图像 |
| test | 152 条 | 评估（已见过场景中的物体） | 实时渲染 |
| unobject | 164 条 | 评估（未见过的物体类别） | 实时渲染 |
| unscene | 173 条 | 评估（未见过的场景） | 实时渲染 |

## 对于我们项目的影响

**我们的系统不需要下载完整数据集来做闭环测试。**

| 阶段 | 需要什么 |
|---|---|
| 实时闭环（连接 AirSim） | 不需要数据集，用 AirSim.exe 实时渲染 |
| 离线评估 | 需要数据集的起始位姿和目标位置 |
| 训练自己的 LoRA | 需要完整数据集 + 训练流程 |

## 类比

就像用自动驾驶数据集训练模型（看录好的视频），然后去真实的路上测试（摄像头实时拍画面）。训练和评估看到的是不同的画面。

## 为什么评估时不直接用预录图像

如果评估时也用车里的预录图像，跑一步模型预测一个 waypoint，如果这个 waypoint 不等于数据集里的下一步位置，就没有那一步的图像了——**卡住了**。

所以必须用仿真器实时渲染，才能支持任意 waypoint 执行后的下一步观测。
