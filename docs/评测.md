> 如何在 Linux 服务器上使用 TravelUAV 仿真环境 + 数据集 + API 系统跑批量评测，得到 SR/NE/SPL 等论文指标。

### 2.3 训练 vs 评测

```
训练:
  输入: 数据集预录图像（固定）
  过程: 模型看图 → 预测waypoints → 与GT waypoints对比 → 反向传播
  输出: 模型权重

评测:
  输入: 仿真器实时渲染图像（每步不同）
  过程: 模型新图 → 预测waypoints → AirSim执行 → 新位置 → 新图 → ...
  输出: 轨迹终点 vs GT目标位置 → SR/NE/SPL
```

**评测不需要预录图像**。图像由仿真器实时渲染，因为模型走出的轨迹和 GT 不同。

## 三、评测流程

### 3.1 多场景自动切换（推荐）

一步搞定，无需手动管理 UE4 进程。`SceneManager` 自动扫描场景、启动/杀死 UE4：

```bash
cd /path/to/uni-lavira-code-main

# test split
python eval/run_eval.py \
    --dataset /data/sakura/data/UAV-VLN-FOV/test \
    --env_root /data/sakura/data/TravelUAV_env \
    --gpu 0

# unobject split
python eval/run_eval.py \
    --dataset /data/sakura/data/UAV-VLN-FOV/unobject \
    --env_root /data/sakura/data/TravelUAV_env \
    --gpu 0

# unscene split
python eval/run_eval.py \
    --dataset /data/sakura/data/UAV-VLN-FOV/unscene \
    --env_root /data/sakura/data/TravelUAV_env \
    --gpu 0
```

自动流程：

```
数据集场景列表: [ModularEuropean, ModularPark, Town01, ...]
     │
     ▼ SceneManager._scan_scenes() 扫描 .sh
场景映射: {ModularEuropean → .../ModularEuropean.sh, ...}
     │
     ▼ 逐场景循环
start("ModularEuropean") → bash ...sh -RenderOffscreen -GraphicsAdapter=0
     │ wait 15s → AirSim 就绪
     ▼
跑该场景所有 episode
     │
     ▼ stop() → kill 进程
start("ModularPark") → ...
```

### 3.3 到达判定

与 3DG-VLN 一致，使用 **GT 世界坐标距离**：

```python
pos = client.get_pose()[0]
dist_to_gt = |pos - ep["target"]|    # 欧氏距离
if dist_to_gt < 10.0:               # SUCCESS_RADIUS = 10m
    task_done = True
```

不依赖前视图 bbox 深度（飞过头顶也能正确判定到达）。

### 3.4 指标含义

| 指标 | 全称 | 计算 | 说明 |
|------|------|------|------|
| **NE** | Navigation Error | `|P_final - P_gt|` | 终点到 GT 目标的欧氏距离, 越小越好 |
| **SR** | Success Rate | `NE ≤ 10m` | 成功率, 越高越好 |
| **OSR** | Oracle Success Rate | 过程中任何一步曾进入 10m | 宽松成功率 |
| **TL** | Trajectory Length | 累计飞行路径长度 | 所有步位移之和 |
| **SL** | Straight Line | 起点到 GT 目标的直线距离 | |
| **SPL** | Success weighted by Path Length | `SR × SL / max(TL, SL)` | 路径效率, 越高越好 |

原理：纯几何计算，不依赖任何模型或图像。

```
P_final (轨迹终点)  vs  T_gt (mark.json 里的 target.position)
NE = |P_final - T_gt|
SR = NE ≤ 10m
```

### 3.5 开环 vs 闭环

| | eval/openloop_eval.py | eval/run_eval.py |
|---|---|---|
| **需要 AirSim** | ❌ | ✅ |
| **需要 TravelUAV 环境** | ❌ | ✅ |
| **看图次数** | 只看第一帧 | 每步重新看（最多 100 步） |
| **速度** | 秒级/条 | 分钟级/条 |
| **到达判定** | 无（一次性规划终点） | GT 世界坐标距离 < 10m |
| **用途** | 快速筛选、调 prompt | 最终论文指标 |

开环原理：读数据集第一帧 → 调 API → waypoints 终点转世界坐标 → 对比 GT。

```bash
# 笔记本上就能跑，不需要 AirSim
python eval/openloop_eval.py --dataset /data/sakura/data/UAV-VLN-FOV/test
python eval/openloop_eval.py --dataset /data/sakura/data/UAV-VLN-FOV/unobject
python eval/openloop_eval.py --dataset /data/sakura/data/UAV-VLN-FOV/unscene
```

## 四、配置切换

`config/default.yaml` 中改 `AIRSIM_IP` 即可切换本地/远程 AirSim：

```yaml
SIM:
  AIRSIM_IP: ""                    # 本地评测 (代码和 UE4 同机)
  AIRSIM_IP: "172.27.143.102"      # 远程评测 (代码在笔记本, UE4 在服务器)
  AIRSIM_PORT: 41451
  CAPTURE_MODE: batch              # batch | parallel
  CAPTURE_PROFILE: auto            # auto | front_depth | front_down | front_down_front_depth | front_down_both_depth
```

### 4.1 抓图默认策略

`CAPTURE_PROFILE: auto` 时，程序会根据规划器自动选择抓图内容：

- `AGENT.PLANNER: api_atomic_planner`
  - 默认抓 `front_down_front_depth`
  - 即：前视图 + 下视图 + 前视深度
- `AGENT.PLANNER: qwen_planner`
  - 默认抓 `front_down`
  - 即：前视图 + 下视图

补充说明：

- 这个两图默认主要是给本地微调 Qwen 推理省时用的
- 离线评测 `run_eval.py` 仍可用 GT 世界坐标判定到达
- 但交互式 Web 闭环如果你也用两图模式，就不会有“深度阈值自动停止”
- 如需保留深度阈值自动停止，请改成 `front_down_front_depth`

如果你想强制覆盖默认行为，可以直接改：

```yaml
SIM:
  CAPTURE_PROFILE: front_down_both_depth
```

### 4.2 并发抓图开关

`CAPTURE_MODE` 控制 AirSim 抓图方式：

- `batch`：一次 `simGetImages(...)` 批量请求，兼容性最好
- `parallel`：多个 AirSim client 并发请求，通常更快，但属于实验性模式

启用并发抓图：

```yaml
SIM:
  CAPTURE_MODE: parallel
```

测速脚本：

```bash
python tools/benchmark_airsim_capture.py --runs 3 --local
```

你当前实测结果中，`dual_parallel4` 相比 `dual_batch` 平均快约 25%。

## 五、远程多场景评测与 SSH 免密

如果代码在本地电脑、TravelUAV 场景在服务器上，推荐先配置 SSH 免密登录。否则 `run_eval.py` 在每次 `ssh/scp` 切场景时都会反复要求输入密码。

### 5.1 配置文件

先确认 `config/default.yaml` 中的远端 AirSim 和场景服务器配置：

```yaml
SIM:
  AIRSIM_IP: "172.27.143.102"
  AIRSIM_PORT: 41451

EVAL:
  REMOTE_HOST: sakura-airsim
  REMOTE_USER: ""
  REMOTE_PORT: 22
```

这里推荐让 SSH 走别名、让 AirSim 走 IP：

- `EVAL.REMOTE_HOST: sakura-airsim` 用于 `ssh/scp` 免密切场景
- `SIM.AIRSIM_IP: 172.27.143.102` 用于 AirSim RPC 抓帧、读位姿、执行动作

不要把别名写进 `REMOTE_USER`，否则程序会拼成 `别名@IP`，导致 SSH 登录失败。

### 5.2 生成专用 SSH key

不要覆盖已有的 `id_rsa`，单独生成一把给服务器使用：

```bash
ssh-keygen -t rsa -b 4096 -f C:\Users\86136\.ssh\id_rsa_sakura
```

如果希望后续完全免输入，`Enter passphrase` 直接回车留空即可。

### 5.3 查看并复制公钥

```bash
type C:\Users\86136\.ssh\id_rsa_sakura.pub
```

把输出的整行内容复制下来。注意要包含开头的 `ssh-rsa`，整行不能换行。

### 5.4 将公钥加入服务器

先登录服务器：

```bash
ssh sakura@172.27.143.102
```

在服务器上执行：

```bash
mkdir -p ~/.ssh
chmod 700 ~/.ssh
touch ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
nano ~/.ssh/authorized_keys
```

把刚才复制的整行公钥粘贴进去，保存退出。

### 5.5 在 Windows 配置 SSH 别名

本机创建或编辑：

```bash
notepad C:\Users\86136\.ssh\config
```

写入：

```text
Host sakura-airsim
    HostName 172.27.143.102
    User sakura
    IdentityFile C:\Users\86136\.ssh\id_rsa_sakura
```

### 5.6 测试是否免密成功

先测试登录：

```bash
ssh sakura-airsim
```

再测试文件传输：

```bash
scp E:\uni-lavira-code-main\eval\scene_manager.py sakura-airsim:/tmp/
```

如果这两步都不再要求输入密码，说明 `run_eval.py` 使用的 `ssh/scp` 也已经可以免密。

### 5.7 运行远程多场景评测

```bash
python eval/run_eval.py ^
  --dataset E:\AGPReID\data\UAV-VLN-FOV-DATA\test\test ^
  --env_root /data/sakura/data/TravelUAV_env ^
  --gpu 0
```

其中：

- `--dataset` 是本地可访问的数据集路径
- `--env_root` 是服务器上的 TravelUAV 场景根目录
- `SIM.AIRSIM_IP` 决定本地代码连接哪台 AirSim
- `EVAL.REMOTE_HOST / REMOTE_USER` 决定本地代码通过 SSH 去哪台服务器切场景

## 六、常见问题

### Q: 为什么必须用仿真器实时渲染，不能直接用数据集预录图像？
A: 闭环每步输出 waypoint → 无人机飞到新位置 → 数据集没有新位置的图像 → 卡住。必须仿真器实时渲染。

### Q: `-RenderOffscreen` 看不到画面？
A: 无窗口模式，GPU 渲染到显存，通过 AirSim API 取 numpy 数组。评测不需要看画面。

### Q: 3DG-VLN 和 TravelUAV 为什么能在同一环境跑？
A: 3DG-VLN 借用了 TravelUAV 的 UE4 地图重新采集数据。两者 mark.json 坐标指向同一物理位置。

### Q: 到达判定为什么不用 bbox 深度？
A: 飞过头顶时前视看不到目标 → bbox 深度不可用。GT 世界坐标是唯一的可靠信号，与 3DG-VLN 一致。

### Q: 代码在笔记本还是服务器？
A: 代码放哪都行。改 `AIRSIM_IP` 切换本地/远程。API 服务的 URL 也在 `config/default.yaml` 中配置。
