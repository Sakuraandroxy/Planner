# 离线批量评测流程

> 如何在 Linux 服务器上使用 TravelUAV 仿真环境 + 数据集 + API 系统跑批量评测，得到 SR/NE/SPL 等论文指标。

---

### 2.2 .sh 是什么

`.sh` 不是地图本身，是启动脚本。真正的结构：

```
ModularEuropean/LinuxNoEditor/
├── ModularEuropean.sh          ← 启动脚本（设置环境变量+启动二进制）
├── ModularEuropean             ← UE4 打包可执行文件（几GB）
├── ModularEuropean/Binaries/   ← 游戏引擎 + AirSim 插件

```

### 2.3 数据集

```
UAV-VLN-FOV/
├── train/         ← 2228条, 训练用（图像+GT waypoints）
├── test/          ← 152条, 评测 Seen（已见场景, 不同目标）
├── unobject/      ← 164条, 评测 Unseen Object（未见物体类别）
├── unscene/       ← 173条, 评测 Unseen Map（未见场景）
└── meta/          ← instructions.json, map_spawnarea_info.json

每条轨迹结构:
  SceneName/
  └── traj_uuid/
      ├── mark.json        ← 起始位姿 + GT目标位置
      ├── obj_des.json      ← 指令文本
      ├── FrontCamera/      ← 预录前视图（训练用）
      ├── DownCamera/       ← 预录下视图（训练用）
      └── log/              ← 每帧位姿（训练时算GT waypoints用）
```

### 2.4 训练 vs 评测

```
训练:
  输入: 数据集预录图像（固定）
  过程: 模型看图 → 预测waypoints → 与GT waypoints对比 → 反向传播
  输出: 模型权重

评测:
  输入: 仿真器实时渲染图像（每步不同, 依赖模型走出的轨迹）
  过程: 模型新图 → 预测waypoints → AirSim执行 → 新位置 → 新图 → ...
  输出: 轨迹终点 vs GT目标位置 → SR/NE/SPL
```

**评测不需要用数据集里的预录图像。** 图像由仿真器实时渲染，因为模型走出的轨迹和 GT 不同，数据集的图像对不上新位置。

## 三、评测流程

### 3.1 启动仿真器

```bash
# 服务器上, 在 3DG-VLN 或 TravelUAV 的 airsim_plugin 目录
cd /data/sakura/AVLN/TravelUAV/airsim_plugin

python AirVLNSimulatorServerTool.py \
    --port 30000 \
    --root_path /data/sakura/data/TravelUAV_env \
    --gpus 0
```

这个脚本做的事：
1. 监听 30000 端口等待评测请求
2. 收到请求时 `subprocess.Popen("bash ModularEuropean.sh -RenderOffscreen -GraphicsAdapter=0")`
3. 启动 UE4 无窗口模式，加载地图
4. 每张地图自动分配独立端口（30001, 30002...）

### 3.2 运行评测

```bash
cd /path/to/uni-lavira-code-main

# 多场景自动切换（推荐）—— 自动启动/切换 UE4 场景
python eval/run_eval.py \
    --dataset /path/to/UAV-VLN-FOV/test \
    --env_root /data/sakura/data/TravelUAV_env \
    --gpu 0

# 单场景模式 —— 手动启动 UE4 后只跑指定场景
python eval/run_eval.py \
    --dataset /path/to/UAV-VLN-FOV/test \
    --scene ModularEuropean
```

多场景模式自动完成：
1. 按场景分组数据集
2. 启动对应 UE4 场景 (`bash ModularEuropean.sh -RenderOffscreen`)
3. 跑该场景所有轨迹
4. 自动 kill 旧 UE4 进程、启动下一场景
5. 全部跑完 → 汇总输出

### 3.3 run_eval.py 核心逻辑

```python
# 1. 扫描数据集
episodes = discover_episodes(dataset_path)
# → [{name, scene, start, target, instruction, target_obj}, ...]

# 2. 逐条跑闭环
for ep in episodes:
    metrics = MetricsTracker(ep["target"])  # GT目标位置

    # 初始位姿
    client.move_to_position(ep["start"])

    # 闭环循环
    for step in range(100):
        front, down, depth = client.get_dual_view()      # 抓帧
        detection = detector.detect(front, target_obj)    # 检测
        result = planner.plan(front, down, instruction)   # 规划(调API)
        client.execute_waypoints(result.waypoints)        # 执行
        metrics.record_step(pos_final)                    # 记录

        if done:
            break

    # 输出单条指标
    print(f"NE={metrics.ne:.1f}m SR={metrics.sr} SPL={metrics.spl:.2f}")

# 3. 汇总
print(f"SR={sr/n*100:.1f}%  NE={mean(ne_list):.1f}m  SPL={mean(spl_list):.3f}")
```

### 3.4 指标含义

| 指标 | 全称 | 计算 | 说明 |
|------|------|------|------|
| **NE** | Navigation Error | `\|P_final - P_gt\|` | 终点到GT目标的欧氏距离(米), 越小越好 |
| **SR** | Success Rate | `NE ≤ 10m ? 成功 : 失败` | 成功率, 越高越好 |
| **OSR** | Oracle Success Rate | 过程中任何一步曾进入成功半径 | 宽松成功率 |
| **TL** | Trajectory Length | 累计飞行路径长度 | 所有步位移之和 |
| **SL** | Straight Line | 起点到GT目标的直线距离 | |
| **SPL** | Success weighted by Path Length | `SR × SL / max(TL, SL)` | 路径效率, 越高越好 |

### 3.5 评测原理

```
评测 = 比大小

你的轨迹终点  vs  数据集GT目标位置
     ↓                ↓
  P_final          T_gt (来自 mark.json["target"]["position"])

NE  = |P_final - T_gt|    ← 就是欧氏距离
SR  = NE ≤ 10m            ← 论文标准

不依赖任何模型、API、图像。纯几何计算。
```

### 3.6 开环 vs 闭环评测

| | eval/openloop_eval.py | eval/run_eval.py |
|---|---|---|
| **需要 AirSim** | ❌ | ✅ |
| **需要 TravelUAV 环境** | ❌ | ✅ |
| **看图次数** | 只看第一帧 | 每步重新看（最多100步） |
| **速度** | 秒级/条（取决于API延迟） | 分钟级/条 |
| **准确性** | 低估（只看一帧不能纠偏） | 论文级（闭环可修正） |
| **用途** | 快速筛选、调 prompt、验证管线 | 最终出论文指标 |

**开环原理**：读取数据集第一帧图像 + 起始位姿 → 调 planner → waypoints 终点转世界坐标 → 对比 GT。

```bash
# 开环评测——不需要 AirSim，不需要 GPU，在笔记本上就能跑
python eval/openloop_eval.py --dataset /path/to/UAV-VLN-FOV/test
python eval/openloop_eval.py --dataset /path/to/UAV-VLN-FOV/unobject
python eval/openloop_eval.py --dataset /path/to/UAV-VLN-FOV/unscene

# 只跑某个场景
python eval/openloop_eval.py --dataset /path/to/UAV-VLN-FOV/test --scene ModularEuropean
```

## 四、为什么不能离线评测（不跑仿真器）

```
闭环每步需要: 前视图 + 下视图 + 深度
             → detector → planner → waypoints → AirSim执行

数据集给的是: 沿 GT 轨迹的预录图像

矛盾:
  你的模型输出了一个 waypoint ≠ 数据集的下一步位置
  → 无人机飞到了新位置
  → 数据集没有那个新位置的图像
  → 卡住

所以必须用仿真器实时渲染 → 才能支持任意 waypoint 执行后的新观测
```

## 五、环境隔离

TravelUAV 仿真环境是 UE4 Linux 二进制，**不需要 Python 环境、不需要 conda、不需要 torch**。

你的 API 系统在笔记本/服务器上运行现有环境即可，通过网络连接服务器上的 AirSim。

目前需要新建的唯一环境：**无**。仿真器是二进制程序，直接运行；评测脚本复用你的 Uni-LaViRA 现有环境。

## 六、常见问题

### Q: 服务器跑仿真看不到画面？
A: `-RenderOffscreen` 模式下无窗口，GPU 渲染画面到显存中，你的模型通过 AirSim API 拿 numpy 数组。评测跑几百条轨迹不需要看画面，最终要的就是那行指标。

### Q: TravelUAV 环境和 Blocks.exe 有什么区别？
A: 本质上都是 UE4+AirSim 打包的可执行文件。区别是地图内容：Blocks.exe 是彩色方块，TravelUAV 是逼真城市/小镇/公园。TravelUAV 只打包了 Linux 版，没有 Windows 版。

### Q: 3DG-VLN 和 TravelUAV 的数据集为什么能在同一个环境跑？
A: 3DG-VLN 借用了 TravelUAV 的 UE4 地图，在上面重新采集了自己的数据集。两者 mark.json 里的坐标指向同一套地图的物理位置。

### Q: 评测结果对标论文吗？
A: 评测逻辑完全一致（数据集GT + 闭环飞行 + 终点对比），唯一变量是规划器不同。你的 API 系统产出的 SR/NE/SPL 和论文数字可以直接对比。

### Q: 能否先在本地离线测试？
A: 可以。直接用**开环评测**，不需要 AirSim、不需要 GPU：

```bash
python eval/openloop_eval.py --dataset /path/to/UAV-VLN-FOV/test
```

原理：读数据集第一帧图像 → 调 API → waypoints 终点转世界坐标 → 对比 GT。

### Q: AirSim 端口是怎么确定的？
A: 没在 `settings.json` 里写就去默认值 `41451`。AirSim 配置文件位置：
- Windows: `C:\Users\<用户名>\Documents\AirSim\settings.json`
- Linux: `~/Documents/AirSim/settings.json`

如需修改端口，在 `settings.json` 顶层加 `"ApiServerPort": 41452`。

### Q: 代码在笔记本还是服务器？配置怎么切换？
A: 代码放哪都行，只需改一行配置切换本地/远程：

```yaml
# config/default.yaml
SIM:
  AIRSIM_IP: ""              # 本地留空 = localhost
  AIRSIM_PORT: 41451
```

连接远程服务器时：
```yaml
SIM:
  AIRSIM_IP: "172.27.143.102"  # 服务器 IP
  AIRSIM_PORT: 41451
```

`sim/airsim_client.py` 已支持从 config 读取 IP/端口，不需要改代码。

### Q: 测试集有多个场景，如何一次跑完？
A: 使用 `--env_root` 参数自动切换：

```bash
python eval/run_eval.py --dataset /path/to/test \
    --env_root /data/sakura/data/TravelUAV_env --gpu 0
```

原理：`eval/scene_manager.py` 管理 UE4 进程生命周期，`run_eval.py` 按场景分组数据自动切换。核心文件：
- `eval/scene_manager.py` — UE4 进程管理（启动/杀死/复用）
- `eval/run_eval.py:evaluate_multi_scene()` — 多场景调度逻辑
