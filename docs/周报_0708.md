# 规划器组周报(2026-7-8)

## 一、本周工作

### 1. 基于 3DG-VLN 数据集实现离线评测流程

本周完成了 **3DG-VLN: 3D-Geometric Vision-and-Language Navigation** 数据集与评测流程的对接，并基于 **TravelUAV** 提供的仿真场景实现了离线评测。  
3DG-VLN 使用的是 UAV-VLN-FOV 数据集，我们基于 TravelUAV 提供的 AirSim/UE 场景，完成了按场景自动切换、按轨迹批量运行和指标自动统计的评测链路。

当前支持的测试划分包括：

| split | 含义 | 轨迹数 |
|---|---|---:|
| `test` | Seen 场景 | 152 |
| `unobject` | Unseen Object | 164 |
| `unscene` | Unseen Map | 173 |
| **总计** | - | **489** |

当前离线评测可以输出的核心指标包括：

| 指标 | 含义 | 具体计算方法 |
|---|---|---|
| **SR** | Success Rate，成功率 | 轨迹结束后，如果终点到目标点距离小于成功半径，则记为成功 |
| **NE** | Navigation Error，终点到目标的距离 | 直接计算最终位置和目标位置的欧氏距离 |
| **OSR** | Oracle Success Rate，过程中是否曾进入目标范围 | 只要飞行过程中任意一步进入成功半径，就记为成功 |
| **SPL** | 路径效率指标，兼顾是否成功和路径是否绕远 | 成功情况下，用起点到目标的直线距离除以实际飞行路径长度，越接近 1 越好 |

这部分工作的意义是：后续无论我们换本地模型还是云端 API，都可以放到同一套评测框架下做公平比较。

### 2. 接入 3DG-VLN 使用的目标检测器 GroundingDINO

本周将目标检测模块切换到 **GroundingDINO: Marrying DINO with Grounded Pre-Training for Open-Set Object Detection**，用于替代原来“先用 VLM 输出目标框”的做法。  
它的作用比较直接：输入当前图像和英文目标名，输出目标 bbox，再结合深度图得到目标距离。

从当前闭环运行日志来看，目标检测阶段速度已经比较稳定：

| 步数 | 检测耗时 |
|---|---:|
| Step 1 | 1.58s |
| Step 2 | 2.39s |
| **平均** | **约 2.0s/步** |

在这组任务中，检测置信度稳定为 **0.95**，并且都成功锁定了目标车辆。  
整体来看，目标检测已经不是当前系统里最慢的一环，主要耗时仍然在 AirSim 取图和动作执行。

### 3. 实现世界模型接口

本周完成了 **世界模型接口** 的对接，用来给规划器生成的多条候选轨迹打分。

当前流程比较简单：

1. 规划器先生成多条候选轨迹。
2. 程序把当前前视图、下视图、任务指令和候选轨迹一起发送给世界模型。
3. 世界模型返回每条候选的分数，以及最终选择的轨迹下标。
4. 系统执行分数最高的那一条轨迹。

当前输入主要包括：

- 前视图、下视图
- 当前任务指令
- 候选轨迹的 waypoints / actions / delta 等信息

当前输出主要包括：

- `best_index`：最优轨迹下标
- `scores`：每条候选轨迹的分数
- `reasoning`：简单的选择理由

这部分工作的意义是：后续我们不只是“让规划模型自己选”，还可以增加一个独立打分模块，提高轨迹选择的稳定性。
