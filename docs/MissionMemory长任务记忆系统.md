# MissionMemory 长任务记忆系统及避障

更新时间：2026-08-05

当前版本的planner在原有“当前视觉检测 + VLM 轨迹规划”的基础上，加入了轻量级长任务记忆系统。

## 1. 为什么需要长任务记忆

原始planner更依赖当前视野。对于短任务问题不大，但长任务会出现目标丢失或目标切换。例如：

```text
先飞到白车旁边，再飞到灌木丛旁边的红车旁边
```

如果一开始红车在视野里，但系统只关注当前阶段的白车，飞到白车附近后机体偏航，红车可能离开视野，后续阶段就容易失去方向。MissionMemory的作用就是在一个完整长任务内部，提前记住已经看到过的关键目标和锚点，让后续小任务不必完全从零开始搜索。

## 2. MissionMemory记住什么

MissionMemory只保存目标级摘要，不保存原图、视频、完整深度图、密集点云或全局地图。每个目标实例主要记录：

```text
目标类别和描述
估计世界坐标
置信度
位置不确定性
观测次数和最近观测时间
目标footprint半径
少量外观摘要
当前小任务的目标锁定状态
```

例如有三辆红车时，memory不只是记录一个 `red car`，而是维护多个实例，并尽量区分“第一辆红车”“第二辆红车”“灌木丛旁边的红车”。这样可以减少多实例场景中的目标切换。

这里的“不确定性”表示memory对目标位置的把握程度。远距离、遮挡、检测框不准、深度噪声大或很久没有重新观测，都会让不确定性变大。完成任务时不会只看memory坐标，而是会结合不确定性、置信度、当前视觉和几何关系一起判断。

## 3. Memory 的工作流程

一个长任务会被拆成多个小任务，memory在这些小任务之间共享。流程大致是：

```text
任务解析后：在飞行开始前执行一次目标bootstrap
执行当前阶段：持续更新当前目标memory
正常规划抓图：同步取得RGB、深度和抓图位姿
飞行过程中：约每4s将一个未来目标提交后台检测
主飞行循环：不等待后台检测，继续检查路径进度和到达半径
后台结果返回：由主线程更新memory，过期结果直接丢弃
切换到后续阶段：用已记录memory提供大致方向和目标实例先验
获得新的可靠视觉：继续校准memory
长任务结束：释放本次任务memory
```

需要强调的是，memory不会凭空创造目标位置。如果后续红车一开始被白车挡住，系统只知道任务里有红车这个未来目标，但不会生成一个假的高置信坐标。只有红车真正被观测到后，才会写入可靠 memory。

## 4. 当前目标丢失和后续目标未观测的区别

这两个机制不同。

当前小任务目标丢失时，会先判断MissionMemory中是否已经存在稳定的锁定实例。如果memory置信度和位置不确定性满足要求，系统会继续使用memory引导当前规划，不会因为单次检测丢失立即停车。如果没有可靠memory，或者靠近目标后的完成确认仍无法看到目标，才会暂停当前执行并主动重定位：先朝记忆方向转向，再按通常90°一次、最多360°的方式原地搜索。

后续小任务目标看不到时，不会为了它打断当前任务。系统只会利用正常规划时已经采集的同批次RGB、深度和位姿做低频机会式观测。现在默认约每 4s 提交一个未来目标进行后台检测，能看到就写入memory，看不到就继续执行当前阶段。

这样设计是为了避免无人机还没完成当前任务，就为了未来目标频繁停下或旋转，影响主任务执行。

## 5. 后续目标后台扫描

飞行中的未来目标机会扫描与正常飞行主循环解耦。主线程在正常规划抓图时，一次性获取同一批次的前视/下视RGB、深度和抓图位姿，然后把这份快照提交给专用的`future_memory_scan`后台线程。后台线程只负责未来目标检测，不再调用AirSim抓图、读取位姿或控制无人机。

后台扫描遵循以下限制：

```text
同一时间最多存在一个未来目标扫描任务
默认每次只检测一个未来目标，其余目标轮询处理
当前目标检测和未来目标检测使用相互隔离的线程池
检测完成后，由主飞行线程非阻塞轮询结果并更新MissionMemory
已经完成阶段或不属于当前长任务的结果会被丢弃
后台扫描耗时较长时，正常飞行和到达判定仍会继续运行
```

运行时会输出以下关键日志：

```text
[FutureScan] submitted：已提交后台扫描
[FutureScan] still_running：扫描仍在运行，但当前飞行继续
[FutureScan] completed：扫描完成并提交memory
[FutureScan] discarded：结果已经过期并被丢弃
```

## 6. 当前视觉和旧memory冲突怎么办

进入某个阶段后，之前阶段积累的memory只是一个带不确定性的先验，主要提供“目标大概在哪、朝哪个方向找”。真正执行该阶段时，如果当前视觉重新稳定看到目标，会用新观测更新memory。

如果当前视觉和memory基本一致，就融合更新，提高置信度、降低不确定性。如果差异很大，系统不会直接用单帧结果覆盖旧 memory，而是先判断是不是同一个目标实例：类别、空间距离、外观摘要、序号关系、锚点关系和stage lock都会参与判断。

因此，当前策略不是只靠视觉，也不是只靠记忆，而是：

```text
当前视觉可靠时，用它校准memory
当前视觉弱或目标近距离丢失时，用稳定memory提供支持
两者冲突较大时，先做实例关联，避免错误切换目标
```


## 7. 当前不足

当前系统仍有一些需要继续加强的地方：

```text
后续目标如果一直未被自然观测到，切换阶段后仍需要更主动的搜索策略
目标必须完整或者大部分出现在视野离，如飞行到某栋大楼旁边时，飞近后无法检测出完整大楼，无法判定任务完成
“左前方白车/右前方红车”等方位限定目前主要保留在自然语言指令中，尚未成为MissionMemory的严格实例选择规则；多辆同类目标同时出现时仍可能锁错实例。
当前Qwen模型给出的轨迹质量仍然较差，并且微调只局限于二维，对于垂直方向的轨迹几乎无法给出（除非任务中明确说上升/下降多少米），对于飞跃前方建筑这种任务尚无法实现。
```

## 总结

MissionMemory让planner能在长任务中记住关键目标和目标实例，避免后续目标丢失、多实例混淆和飞过目标；深度避障层则在轨迹执行前增加本地安全检查，减少直接撞上障碍或目标本体的情况。整体设计重点是轻量、短期、任务相关，适合未来向边缘设备部署。
