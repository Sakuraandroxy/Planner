# 郊区无人车越过航点后卡住

ProjectAirSim 无人车在郊区场景越过第 3 个航点后倒车，随后停在航点旁，直到执行超时。当前的连续执行与载具端口分工见[架构文档](../ARCHITECTURE.md#11-运动与航向控制)。

## 现象与根因

1. 无人车以约 3 m/s 接近航点，实际减速不足以在航点前停下。场景里的后轮是驱动轮，当时的摩擦系数为 `0.0`，抓地力不足也削弱了制动。
2. 越点后，航点落到车身后方。`ContinuousFollower` 按当前位置指向参考点的方向生成世界坐标系速度。`controls_from_reference()` 取该速度沿车头方向的投影，得到负的前向速度，车辆开始倒车，实测倒车速度峰值约为 1.5 m/s。这条倒车命令来自连续跟随器与载具适配层。
3. 倒车后，车头与航段朝向的误差约为 0.02°，位置残差却主要在侧向。复盘记录的总残差为 0.388 m，侧向残差约 0.37 m。跟随器输出的期望速度几乎垂直于车头，取前向投影后约为 0 m/s，车辆就停在了原地。
4. 故障发生时，`reached()` 用 0.3 m 作为到点与驶过航点的横向容差。车辆在两个判据下都无法消费队首航点，最终由 `ContinuousExecution` 报出 `execution_error`。单航点等待上限默认为 60 秒，该次日志累计约 70 秒。

画面里车轮持续转动的现象，复盘时推测与后轮打滑有关。车辆卡住时前向投影已接近零。侧向残差和航点判据足以解释这一阶段为何无法推进。

## 已实施的修正

- [郊区无人车场景配置](../../config/scenes/neighborhood/robot_rover.jsonc)把后轮摩擦系数从 `0.0` 调到 `1.0`，与交流中心场景一致。
- [航点到达判定](../../planner/services/motion/continuous.py)已经区分到点容差和驶过航点的横向容差。[ProjectAirSim 无人车](../../planner/simulators/projectairsim/rover.py)把后者放宽到至少 0.6 米。已驶过航点且仍在走廊内时，只要满足航向判据，就可以消费队首航点。

## 当时的改进提案

若车辆仍会冲过航点，应先用实测制动能力核对规划的减速曲线，再标定 [无人车驱动模型](../../planner/simulators/projectairsim/drive.py)中的 `speed_per_engine_mps` 和 `brake_gain`，并核对巡航速度与航点间距。

当前 `StreamingVehicle` 接收世界坐标系速度和偏航角速度。无人车适配层取前向投影，跟随器通过这一端口无法得知横移约束。复盘提出保留共享的路径跟随逻辑，按载具运动模型生成命令。

- 载具声明 `MotionCapability`，包含运动模型、最大横移速度、最小转弯半径和是否允许倒车。
- 无人机沿用全向速度。阿克曼车在路径上取前视点，用纯跟踪计算曲率，公式为 `κ = 2·sin(α)/Ld`。`α` 是车头与前视点连线的夹角，`Ld` 是前视距离。控制命令由前向速度与曲率或偏航角速度组成，倒车须由任务明确要求。
- 装配时验证跟随器与载具运动模型是否匹配，适配层拒绝载具无法执行的命令。回归用例覆盖直行、急弯、越点和侧向残差，并验证无人机仍可横移、无人车拒收横移命令，以及越点时不会因追逐身后航点而倒车。

另一种提案是让载具端口接收参考位姿，由每套仿真器适配层自行实现局部跟踪。这会重复实现路径跟随，因此当时倾向于把跟随逻辑留在共享层。
