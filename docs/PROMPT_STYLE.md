# 提示词写作规范

提示词是发给模型的指令文本。读者是模型，不是人，但可读性直接决定模型能否稳定照做。本文件定规则，`planner/adapters/prompts/templates/` 下的模板与它们的变量都按它写。

## 1 三条硬规则

1. **一条指令一行。** 一行只表达一件事。两个动作要合在一行，说明它们本来就是同一件事。
2. **每条限制都要能改变输出。** 删掉之后模型行为不变的句子，删掉。写之前先问：不写这条，模型会不会做错？不会就不写。
3. **同一限制只说一次。** 换词重复、先肯定再否定、加「注意」「务必」「请勿」这类强调，都算重复。

## 2 禁止的写法

| 类型 | 例 | 问题 |
| --- | --- | --- |
| 防御性叠甲 | 「该检测观测中的归一化目标框：…；仅属于该观测，不能直接套用到其他图像。」 | 一句话里两个限定在说同一件事：这是哪次观测的框。 |
| 反复声明边界 | 「这不等于任务已完成」「不能当作已确认同一目标」「坐标偏移也不直接证明目标已改变」 | 三条都在讲「证据强度有限」。合并成一句说明当前状态即可。 |
| 元话语 | 「注意」「请确保」「务必记住」「以下内容很重要」 | 不改变输出，只占 token。 |
| 嵌套从句 | 「如果本阶段已建立绑定，则除非当前画面无法识别，否则继续使用原绑定位置。」 | 两重条件写在一句里，模型容易漏一半。拆成两行。 |
| 同义换词 | bbox、bounding box、检测框、目标框混用 | 模型按词对齐行为，换词等于换要求。 |
| 无出处的数值 | 「偏移超过 0.15 就视为改变」 | 要么给单位与来源，要么说明这是经验值。 |

## 3 推荐写法

- 主动语态、简单句。英文每句不超过 20 个词，中文每句不超过 30 字。
- 条件与动作分行：先写触发条件，再写动作。
- 列举用编号或短横线，顺序固定，不加「首先」「另外」这类连接词。
- 用 `must`、`do not`，不用 `please ensure`、`try to avoid`。
- 术语表固定下来，模板与代码注释用同一个词：

| 概念 | 唯一写法 |
| --- | --- |
| 目标框 | `bbox` |
| 表面采样点 | `surface points` |
| 待执行航点 | `queue` / `pending queue` |
| 任务阶段 | `stage` |
| 观测 | `observation` |
| 目标绑定 | `bound` target |

## 4 改写示例

改前：

```
该次位置估计已被本地接受；这不等于任务已完成。
该检测观测中的归一化目标框：${bbox_json}；仅属于该观测，不能直接套用到其他图像。
本阶段已建立目标绑定；当前画面不必独立重新识别完整目标。
该次坐标更新未接受：${rejection}；继续使用原绑定位置。该检测仅为待核实的辅助证据，不能当作已确认同一目标；坐标偏移也不直接证明目标已改变。
该检测观测中模型选择的表面像素：${surface_points_json}；不是完整目标边界。
```

改后：

```
本地已接受本次位置更新。任务未完成。
本次观测的目标框（归一化）：${bbox_json}。此框只对应本次观测。
本阶段已绑定目标。当前画面沿用该绑定，不必重新识别。
本次坐标更新未接受：${rejection}。继续使用原绑定位置。该证据待核实。
本次观测的表面点：${surface_points_json}。表面点不等于目标边界。
```

改动原则：删掉重复限定，把每条事实压成一句，保留所有会影响模型输出的信息（哪次观测、框不等于边界、沿用旧位置）。

## 5 审查清单

模板提交前逐条过：

- [ ] 每一行只做一件事
- [ ] 没有两条句子表达同一限制
- [ ] 没有「注意」「务必」「请注意」这类强调
- [ ] 术语与术语表一致
- [ ] 数值带单位，经验值有标注
- [ ] 删掉的句子都写进了提交正文的对照表，并说明为什么不影响模型行为
