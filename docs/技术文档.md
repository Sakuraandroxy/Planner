# Uni-LaViRA UAV VLN — 技术文档

> 模块化架构，所有组件通过 YAML 配置即插即用。
> 三个核心模块（任务解析、目标检测、轨迹规划）均支持本地部署和云 API 两种模式。

---

## 一、模块总览

```
用户任务 "飞到红色汽车旁边"
  │
  ├─ 1. TaskParser (API: TASK_PARSER_URL)
  │     文本→拆解为阶段列表 [TaskStage, ...]
  │     所有输出字段英文（target/instruction/relation）
  │
  ├─ 2. Detector (API: PLANNER_URL / GroundingDINO)
  │     前视图 + target_query（英文） → bbox + 深度
  │
  ├─ 3. DirectionEstimator (本地, 纯数学)
  │     bbox 像素坐标 → yaw 方向分类
  │
  ├─ 4. Planner ─┬─ api_atomic_planner → API → 原子动作 ["forward 4", "left 30"]
  │              │     输入：前视图 + 下视图 + 深度信息 + 英文 instruction
  │              │     输出：K 条候选（含预计算 delta）+ selected_index
  │              └─ qwen_planner       → 本地微调模型 → waypoints [[dx,dy,dz],...]
  │                    输入：前视图 + 下视图 + 英文 instruction
  │                    输出：5 个 waypoints（机体坐标系，相对起始位置）
  │
  ├─ 5. Executor ─┬─ execute_actions        → rotate_to_yaw + move_to_position
  │                └─ execute_waypoints      → moveOnPathAsync(ForwardOnly)
  │
  └─ 6. 闭环 → 回到步骤 1
```

### 即插即用配置（`config/default.yaml`）

```yaml
AGENT:
  TASK_PARSER: vlm_parser              # 任务解析
  TASK_PARSER_URL: https://api.xxx.com/v1
  TASK_PARSER_MODEL: mimo-v2.5
  TASK_API_KEY: sk-xxx

  DETECTOR: vlm_detector               # 目标检测: vlm_detector | groundingdino
  DETECTOR_URL: ""                     # 空=复用 PLANNER_URL
  DETECTOR_MODEL: ""                   # 空=复用 PLANNER_MODEL
  GROUNDINGDINO_URL: http://x.x.x.x:8003/detect

  PLANNER: api_atomic_planner          # 轨迹规划: api_atomic_planner | qwen_planner
  PLANNER_URL: https://api.xxx.com/v1
  PLANNER_MODEL: mimo-v2.5
  PLANNER_API_KEY: sk-xxx
  PLANNER_CANDIDATE_COUNT: 5           # K 条候选轨迹
  PLANNER_MAX_TRAJECTORY_LENGTH: 5     # 单条轨迹最大动作数
  PLANNER_APPROACH_STOP_MARGIN: 1.0    # 接近停止余量（米）

  DIRECTION: three_dg                  # 方向估计
  STOP_DEPTH_THRESHOLD: 8.0            # 停止深度阈值（米）
  QWEN_WAYPOINT_COUNT: 5              # Qwen 每步 waypoints 数量

SIM:
  CAPTURE_MODE: batch                  # batch | parallel
  CAPTURE_PROFILE: auto                # auto | front_depth | front_down | front_down_front_depth | front_down_both_depth
  # auto 默认:
  # - api_atomic_planner -> front_down_front_depth
  # - qwen_planner       -> front_down
```

### 抓图策略（新增）

- `SIM.CAPTURE_MODE` 控制**怎么抓**：
  - `batch`：一次 `simGetImages(...)` 批量抓取
  - `parallel`：多个 AirSim client 并发抓取（实验性，通常更快）
- `SIM.CAPTURE_PROFILE` 控制**抓什么**：
  - `front_depth`：前视图 + 前视深度
  - `front_down`：前视图 + 下视图
  - `front_down_front_depth`：前视图 + 下视图 + 前视深度
  - `front_down_both_depth`：前视图 + 下视图 + 前视/下视深度
  - `auto`：按规划器自动选

当前默认规则：

- 云端 API 规划器 `api_atomic_planner`：默认抓 `front_down_front_depth`
- 本地微调 `qwen_planner`：默认抓 `front_down`

注意：

- `qwen_planner + front_down` 适合本地两图推理
- 但由于没有实时前视深度，Web 闭环里不会使用“深度 < 阈值”自动停止
- 如果你希望保留深度阈值自动停止，请把 `SIM.CAPTURE_PROFILE` 改成 `front_down_front_depth`

## 二、两种轨迹输出格式

### 格式 A：原子动作（`api_atomic_planner`）

调用云 API（MiMo/GPT-4o 等），输出 K 条候选原子动作。

**输入**：前视图 + 下视图 + 深度信息 + 英文 instruction
**输出**：JSON 含 K 条候选 + selected_index，程序解析后计算每条 delta 供世界模型打分

```json
{
  "selected_index": 0,
  "done": false,
  "scene_analysis": "前方远处有一辆汽车",
  "reasoning_summary": "目标在右前方，先右转再前进",
  "candidates": [
    {"actions": ["forward 30"], "reason": "直行接近", "scale": 1.0},
    {"actions": ["right 10", "forward 28"], "reason": "右前方接近", "scale": 1.0},
    {"actions": ["left 5", "forward 25"], "reason": "左前方绕行", "scale": 1.0}
  ]
}
```

**思考模式**：通过 `extra_body={"thinking": {"type": "disabled"}}` 关闭 MiMo 思考模式，减少不必要 token 消耗。

### 格式 B：相对位移 waypoints（`qwen_planner`）

本地微调 Qwen2.5-VL，输出机体坐标系下的累积位置偏移序列。

| | 内容 |
|---|---|
| **输出格式** | `[[1.01, -0.0, 0.29], [3.49, -0.42, 2.13], ...]` |
| **参照系** | 相对于**当前步起始位置**的机体坐标系（不是世界坐标） |
| **含 yaw** | ❌ 无显式 yaw，靠 AirSim ForwardOnly 自动旋转 |
| **适用场景** | 本地微调 Qwen，3DG-VLN 风格 |
| **训练输入** | 前视图 + 下视图 + 英文指令文本 |

### 微调数据格式（`tools/extract_training_samples.py` 生成）

**真实样本示例**（来自 UAV-VLN-FOV 数据集）：

```json
{
  "messages": [
    {
      "role": "user",
      "content": [
        {"type": "image", "image": "images/xxx_step000095_front.png"},
        {"type": "image", "image": "images/xxx_step000095_down.png"},
        {"type": "text", "text": "Instruction: Fly to the white dog on the grass patch near the brown fence."}
      ]
    },
    {
      "role": "assistant",
      "content": "[[1.01, -0.0, 0.29], [1.94, -0.07, 0.81], [3.49, -0.42, 2.13], [4.8, -0.95, 3.56], [6.08, -1.59, 4.51]]"
    }
  ],
  "images": [
    "images/xxx_step000095_front.png",
    "images/xxx_step000095_down.png"
  ]
}
```

**关键点**：
- 只保留 `Instruction:` 前缀，无其他硬编码字段
- `Previous displacement` / `Current position` / `Stage` 已移除——这些字段在所有样本中都是相同的假值，模型学不到任何有用信息，且推理端也不会传
- waypoints 是**相对于当前步起始位置的机体坐标系累积偏移**，与 `execute_waypoints` 的执行逻辑一致

## 三、仿真器执行（AirSim）

### 执行路径自动选择

```python
result = planner.plan(front_img, down_img, instruction, direction, bbox, depth)

if result.actions:                              # 原子动作路径
    client.execute_actions(result.actions)
else:                                           # waypoints 路径
    client.execute_waypoints(result.waypoints)
```

### `execute_actions` — 原子动作执行

每步独立调用 AirSim API，旋转和位移分开：

```
"forward 47":  move_to_position(x+47, y, z)            # 当前朝向飞行
"left 30":     rotate_to_yaw(yaw - 30°)                 # 原地旋转，悬停 0.2s
"forward 5":   move_to_position(x+5cos30°, y+5sin-30°, z)  # 新朝向飞行
```

### `execute_waypoints(use_forward_only=True)` — Waypoints 执行

机体坐标 waypoints 转世界坐标后一次性提交路径：

```python
path = [start_pos + R_start @ wp_i for wp_i in waypoints]
client.moveOnPathAsync(path, drivetrain=DrivetrainType.ForwardOnly)
# ForwardOnly: 无人机自动面朝每个 waypoint 方向
```

### AirSim 预热

`warmup_capture()` 在连接后立即抓取前视 RGB + 下视 RGB + 深度图，初始化 GPU 渲染管线，避免第一步 ~15s 冷启动。

## 四、世界模型输入转换

### `compute_per_step_deltas(result, start_yaw_deg)` — 统一转换函数

位于 `agent/planner/base.py`，将任意规划器输出转为世界模型可用的逐步 delta 序列。

```python
# result.candidates 每条已预计算 delta：
# {"actions": ["forward 30"], "delta": [30.0, 0.0, 0.0, 0.0]}

for candidate in result.candidates:
    score = world_model.score(candidate["delta"])
    ...

best = max(result.candidates, key=lambda c: c["score"])
client.execute_actions(best["actions"])
```

## 五、基础设施模块

所有横切关注点在独立模块中，业务模块（detector/planner/direction）只含领域逻辑。

### 5.1 API 预热（`agent/common/warmup.py`）

启动时遍历 yaml 所有 API 端点，发送 `{"role":"user","content":"OK"}` 极短请求。自动去重相同 `(url, model)` 的端点。消除第一步调用的冷启动延迟（2-10s）。新增端点只需在 yaml 加配置。

所有 API 调用均带 `extra_body={"thinking": {"type": "disabled"}}` 关闭 MiMo 思考模式。

### 5.2 图像编码缓存（`agent/common/image_encoder.py`）

前视图/下视图 JPEG base64 只编码一次，detector 和 planner 可选复用：

```
入口层（run_airsim_web.py）                    业务模块
ImageEncoder.encode_front(frame)  ──写入缓存──→  VLMDetector.detect()
ImageEncoder.encode_down(down)    ──写入缓存──→    ├→ get_cached_front_b64() → 命中复用
                                                ApiAtomicPlanner.plan()
                                                  ├→ get_cached_front_b64()
                                                  └→ get_cached_down_b64()
```

模块不知道缓存就自己编码，零影响。不改接口，不强制依赖。

### 5.3 后台取帧（`sim/frame_capturer.py`）

程序启动后立即 daemon 线程持续取帧推前端，浏览器打开就能看到实时画面。使用独立 AirSim 连接避免 IOLoop 冲突。

### 5.4 任务解析器（`agent/task_parser/vlm_task_parser.py`）

**所有输出字段强制英文**——无论用户输入中文还是英文：

```
输入: "飞到红色汽车旁边"
输出: instruction="Fly to the red car", target="red car", relation="beside"

输入: "fly to the white man in the ground"
输出: instruction="Fly to the white man in the ground", target="white man in the ground"
```

- `target` → GroundingDINO / 检测器用
- `instruction` → Qwen 规划器 / API 规划器用
- `relation` → 空间关系辅助

**action 阶段数值默认值**：VLM prompt 已指示默认值（forward=10m, backward=5m, left/right=90°, up/down=5m），
代码在 `parse_task_parser_to_stages()` 中做二次兜底——若 VLM 未填 `value`，按 `action` 类型自动补：

| action | 默认 value | 含义 |
|--------|-----------|------|
| `forward` | 10.0 | 前进 10m |
| `backward` | 5.0 | 后退 5m |
| `left` | 90.0 | 左转 90° |
| `right` | 90.0 | 右转 90° |
| `up` | 5.0 | 上升 5m |
| `down` | 5.0 | 下降 5m |

> VLM 正确给出了 `value` 则不走默认值。仅有 `"value": null` 或缺失时才触发兜底。

### 5.5 每步指标（`run_airsim_web.py` 内置 `StepTracker`）

**分项计时**：
```
[TIMING Step 1/20] total=25.6s  cap=0.20s  det=1.32s  plan=6.25s  vlm=7.57s  exec=15.7s
```

| 计时项 | 含义 |
|--------|------|
| `cap` | AirSim 抓帧（一次 RPC 取前视+下视+深度） |
| `det` | bbox 检测 API 调用 |
| `plan` | 轨迹规划 API 调用 |
| `vlm` | det + plan 合计 |
| `exec` | 飞行执行 |
| `total` | 整步耗时 |

**累积指标**：
```
[METRICS Step 2] dist=18.7m  spd=0.2m/s  vlm%=20%  NE=3.1m  conf=0.95  z=48.3→19.7m
```

**论文指标**（基于首次检测估算的目标世界坐标）：

| 指标 | 计算方式 |
|------|---------|
| **NE** | 终点到估算目标的世界距离 |
| **SR** | NE ≤ success_radius |
| **OSR** | 过程中任意步是否曾进入成功半径 |
| **TL** | 累计飞行路径长度 |
| **SL** | 起点到目标的直线距离 |
| **SPL** | SR × SL / max(TL, SL) |

> **注意**：目标世界坐标从首次检测估算（`drone_pos + depth × direction`），不是 ground truth。真实评测需结合数据集标注坐标。

│  0. 启动时：                                                  │

## 十一、四种运行模式的深度来源

闭环模式下，RGB/深度都来自 AirSim 实时渲染；开环模式无实时深度。

### 深度获取原理

```python
# sim/airsim_client.py get_configured_views()
# profile=front_down_front_depth 时会抓:
# - front_center Scene
# - down_center  Scene
# - front_center DepthPerspective
```

### 四种模式

| 模式 | 入口 | 规划器 | 深度来源 |
|------|------|--------|---------|
| **交互式 API** | `run_airsim_web.py` | `api_atomic_planner` | AirSim 前视深度（默认） |
| **交互式 Qwen** | `run_airsim_web.py` | `qwen_planner` | 默认不抓深度，只抓前/下视 RGB |
| **闭环批量评测** | `eval/run_eval.py` | 由 config 决定 | AirSim 实时 |
| **开环批量评测** | `eval/openloop_eval.py` | `api_atomic_planner` | 无 (None) |

切换方式：

- 修改 `config/default.yaml` 中 `AGENT.PLANNER`
- 如需强制覆盖默认抓图内容，再改 `SIM.CAPTURE_PROFILE`
- 如需启用并发抓图，再改 `SIM.CAPTURE_MODE: parallel`

### 深度在 planner 中的使用

```python
# agent/planner/api_atomic_planner.py _build_depth_info()
if depth_meters is None:
    return "深度提示：未获取到有效深度数据..."   # 开环

# 闭环: 从真实深度矩阵取值
target_depth = float(depth_meters[bbox_center_y, bbox_center_x])
# → prompt 含 "目标bbox中心深度=15.2m"
```

**同一个 planner 代码，有深度走真实数据分支，无深度走提示分支。**
